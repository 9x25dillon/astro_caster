# Offline gazetteer — provenance and licence

These two files are what let the birthplace picker work with the network
unplugged. They replaced the app's last two per-device external calls
(GAZ-1..GAZ-4). Neither is hand-edited; both are generated, and `cities.json`
has a tripwire that fails CI if it ever is.

## `cities.json`

| | |
|---|---|
| **Source** | [GeoNames `cities5000`](https://download.geonames.org/export/dump/) |
| **Licence** | **CC BY 4.0** — attribution **required** |
| **Attribution** | `© GeoNames (CC BY 4.0)`, rendered under the picker |
| **Rows** | 69,577 (every populated place of ~5,000+) |
| **Size** | 3.14 MB raw · ~1,299 KB gzip |
| **Generated by** | `backend/tools/gen_gazetteer.py` |
| **Schema** | `1` |

Regenerate, or verify:

```bash
# fetch + unzip cities5000.txt from the URL above, then:
python backend/tools/gen_gazetteer.py --source path/to/cities5000.txt

python backend/tools/gen_gazetteer.py --check                 # offline, what CI runs
python backend/tools/gen_gazetteer.py --check --source …txt   # full regeneration compare
```

### Why the format looks like this

Four decisions, each paid for in bytes:

- **Rows are sorted by population, descending — and population is not stored.**
  The order *is* the ranking. This is the single biggest saving, and it means
  **any change to the generator's sort key silently changes search results.**
  The sort key is total (population, then name, country, admin1) so the artifact
  is byte-identical across runs and machines.
- **Coordinates at 3 decimal places** (~110 m). A city is kilometres across, and
  the numeric lat/lng fields stay authoritative, so more precision is bytes for
  nothing.
- **`tz`, `cc`, `a1` are shared string tables**, referenced by index. There are
  69,577 rows but only ~371 timezones and ~245 countries.
- **`asciiname` is stored only when it differs from `name`** (~79% of the time
  it does not). `""` means "same as name"; the loader re-expands it.

`digest` is a SHA-256 over the payload, recomputable from the file itself —
that is what makes the offline `--check` a real tripwire rather than a
formality.

## `land.json`

| | |
|---|---|
| **Source** | [Natural Earth 110m land](https://github.com/nvkelso/natural-earth-vector) (`ne_110m_land`) |
| **Licence** | **Public domain** — no attribution required (credited anyway) |
| **Size** | 84.5 KB raw · ~27 KB gzip |
| **Transform** | properties dropped; coordinates rounded to 2 dp (~1.1 km); rounding-duplicate points collapsed; rings re-closed |

A 110m outline is for **coarse placement only**. City search is the precise
path, and the numeric fields remain authoritative — the map is for orientation
and for placing somewhere the gazetteer does not carry.

## Why both are precached

`vite.config.ts` precaches these (`globPatterns` includes `json`, and
`maximumFileSizeToCacheInBytes` is raised to 5 MiB because `cities.json`
exceeds workbox's 2 MiB default and would otherwise be **silently dropped** from
the manifest — an app that looks fine until it is offline).

Precache rather than runtime-cache was an operator decision: a visitor's *first*
ceremony has to work offline, and a birthplace search that needs the network
would contradict the exact claim this change exists to make true.

## The claim these files make honest

Before GAZ-4, typing a birthplace sent it to `nominatim.openstreetmap.org`, and
panning the map told `basemaps.cartocdn.com` which part of the world was being
examined. Both are gone. `frontend/e2e/no-external.spec.ts` drives the picker
and asserts zero external requests; its ledger of permitted hosts is empty and
must stay empty.
